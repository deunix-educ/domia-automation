# ADR 0065 — VPN : wg-easy 15 (AGPL-3.0) en réseau hôte, première configuration par son API

Statut : **implémenté** (2026-11-25, lots 1 à 3 ; pas encore publié). Clôt le point « licence de wg-easy » de la feuille de route et de [À améliorer](../to-improve.md).

## Contexte
Le profil facultatif `vpn` utilisait `ghcr.io/wg-easy/wg-easy:14`. La version 14 est sous licence **CC BY-NC-SA 4.0** (usage non commercial seulement, constaté dans son fichier `LICENSE` au tag v14.0.0), alors que DomiNet est AGPL-3.0 : une installation en entreprise avec le VPN activé l'utiliserait hors de sa licence. La version 15 est AGPL-3.0 (constaté au tag v15.0.0). C'est une réécriture complète : les variables d'environnement de la 14 (`PASSWORD_HASH`, `WG_HOST`, `WG_POST_UP`, ...) ont disparu, la plupart des réglages sont dans son interface web, et le format des données a changé.

Le VPN du propriétaire n'était pas encore utilisé (2026-11-25) : aucun appareil à conserver.

## Options
- **A. Rester en 14 et documenter la licence.** Aucun travail, mais la limite demeure et le projet ne peut pas présenter le VPN comme utilisable par des entreprises.
- **B. La version 15 telle que son fichier compose officiel la présente** (réseau en pont, ports 51820/51821 publiés, adresses propres). Simple, mais le tunnel se termine alors dans un conteneur : DomiNet, qui écoute sur la machine, ne serait joignable qu'au travers d'une traduction d'adresses vers le réseau local.
- **C. La version 15 en réseau hôte** (la configuration « routée » documentée par wg-easy) : l'adresse du tunnel vit sur la machine. DomiNet y est joignable comme avant. **Choisie.**
- **D. Retirer le profil VPN.** L'accès à distance est alors laissé à l'utilisateur.

## Décision
Option C.
- **Compose.** `ghcr.io/wg-easy/wg-easy:15`, `network_mode: host`, `/dev/net/tun`, un **volume neuf** `wg-easy15-data` (la version 15 ne lit pas les données de la 14). Les valeurs du premier démarrage (`INIT_*`) viennent de `.env` : `DYNDNS_HOST`, `WG_SUBNET`, `WG_SUBNET6`, `WG_DEFAULT_DNS`, `WG_ALLOWED_IPS`. L'administrateur est `admin`, son mot de passe est `WG_ADMIN_PASSWORD`.
- **Profil.** Activé par `WG_ADMIN_PASSWORD`, ou par le `WG_ADMIN_HASH` d'une installation faite pour la 14 : un mot de passe est alors généré dans `.env` et le VPN repart vide sur le volume neuf (changement incompatible, indiqué dans la note de version).
- **Première configuration par l'API.** Ce qui n'a pas de variable d'environnement est réglé **une seule fois** par `tools/prod.sh up` (`wg_configure`), par un script exécuté dans le conteneur de wg-easy (il embarque Node et partage le réseau de la machine) : les règles du pare-feu, l'interface réseau utilisée pour la traduction d'adresses (l'interface par défaut de la machine) et le keepalive (25 s). Il n'agit que tant que les règles sont celles par défaut ; ensuite les réglages appartiennent à l'administrateur et `make prod-up` n'y touche plus.
- **Migration.** `make prod-export` sauvegarde `wg-easy15-data` ; `make prod-import` arrête wg-easy, vide le volume, le restaure. Une archive au format de la version 14 est signalée et non restaurée.

## Conséquences
- Le VPN n'a plus de limite de licence ; `docs/licenses.md` le dit.
- **Incompatible pour une installation qui utilisait le VPN avec la 14** : les appareils sont à recréer ; l'ancien volume reste en place.
- L'interface de wg-easy est servie en HTTP simple sur le réseau domestique (`INSECURE=true`), comme en 14. Le port 51821 ne doit pas être redirigé ([Sécurité](../security.md)).
- DomiNet dépend de la stabilité de l'API de wg-easy 15 pour la première configuration ; si elle change, `wg_configure` échoue avec un message et les réglages restent faisables dans l'interface.

## Tel que construit (2026-11-25)
Constats de la répétition (piles jetables sur le poste de développement, vrai tunnel depuis un conteneur client) :
- **Les règles de pare-feu par défaut ne marchent pas avec les nftables de Docker.** Elles appellent `iptables` (tables *legacy*) alors que la politique de `FORWARD` est `DROP` dans nftables : le tunnel montait mais le réseau local restait injoignable. Les règles doivent nommer `/usr/sbin/iptables-nft`, comme celles de la 14.
- **L'interface par défaut du NAT est `eth0`**, fausse sur une machine dont l'interface s'appelle autrement (`eno1`) : elle est réglée sur l'interface de la route par défaut.
- **`INIT_IPV4_CIDR` est ignoré sans `INIT_IPV6_CIDR`** (le groupe doit être complet).
- **Les règles par défaut peuvent s'exécuter deux fois** (l'interface redémarre après la première configuration) : les règles *legacy* sont supprimées en boucle avant l'enregistrement des nouvelles, donc rien ne reste sur la machine après `down`.
- **L'API accepte l'authentification HTTP Basic** (`admin:<mot de passe>`), ce qui rend le script possible sans session.
- `make check-migrate` exerce maintenant le VPN : le client et la clé du serveur survivent à un export et à un import.
- **Non fait** : un tunnel depuis un vrai appareil à travers Internet (seul un conteneur client sur la même machine a été essayé) ; la suppression automatique du volume de la version 14.
