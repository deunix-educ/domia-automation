# ADR 0065 — VPN: wg-easy 15 (AGPL-3.0) in host network, first configuration through its API

Status: **implemented** (2026-11-25, lots 1 to 3; not released yet). Closes the "wg-easy licence" point of the roadmap and of [To improve](../to-improve.md).

## Context
The optional `vpn` profile ran `ghcr.io/wg-easy/wg-easy:14`. Version 14 is licensed **CC BY-NC-SA 4.0** (non-commercial use only, checked in its `LICENSE` file at tag v14.0.0), while DomiNet is AGPL-3.0: an installation in a business with the VPN enabled would use the VPN outside its licence. Version 15 is AGPL-3.0 (checked at tag v15.0.0). It is a complete rewrite: the environment variables of version 14 (`PASSWORD_HASH`, `WG_HOST`, `WG_POST_UP`, ...) are gone, most settings live in its web interface, and its data format changed.

The owner's VPN was not in use yet (2026-11-25), so no device had to be kept.

## Options
- **A. Stay on 14 and document the licence.** No work, but the limit stays and the project cannot present the VPN as usable by businesses.
- **B. Version 15 as its official compose file has it** (bridge network, published ports 51820/51821, its own addresses). Simple, but the tunnel then ends in a container: DomiNet, listening on the host, would only be reached through address translation to the LAN.
- **C. Version 15 in host network** (documented by wg-easy as the "routed" setup), the tunnel address lives on the machine. DomiNet is reachable at it as before. **Chosen.**
- **D. Remove the VPN profile.** Remote access is then left to the user.

## Decision
Option C.
- **Compose.** `ghcr.io/wg-easy/wg-easy:15`, `network_mode: host`, `/dev/net/tun`, a **new volume** `wg-easy15-data` (version 15 does not read version 14 data). The first-start values (`INIT_*`) come from `.env`: `DYNDNS_HOST`, `WG_SUBNET`, `WG_SUBNET6`, `WG_DEFAULT_DNS`, `WG_ALLOWED_IPS`. The administrator is `admin`, its password is `WG_ADMIN_PASSWORD`.
- **Profile.** Enabled by `WG_ADMIN_PASSWORD`, or by the `WG_ADMIN_HASH` of an installation made for 14: a password is then generated in `.env` and the VPN starts empty on the new volume (breaking, stated in the release note).
- **First configuration through the API.** What has no environment variable is set **once** by `tools/prod.sh up` (`wg_configure`), by a script run inside the wg-easy container (it ships Node and shares the host network): the firewall hooks, the network device used for the address translation (the machine's default interface) and the keepalive (25 s). It acts only while the hooks are still the defaults; afterwards the settings belong to the administrator and `make prod-up` does not touch them.
- **Migration.** `make prod-export` saves `wg-easy15-data`; `make prod-import` stops wg-easy, empties the volume, restores it. An archive in the version 14 format is reported and not restored.

## Consequences
- The VPN has no licence limit left; `docs/licenses.md` says so.
- **Breaking for an installation that used the VPN with 14**: devices must be created again; the old volume is left in place.
- The wg-easy interface is served in plain HTTP on the home network (`INSECURE=true`), as it was in 14. Port 51821 must not be forwarded ([Security](../security.md)).
- DomiNet depends on the stability of the wg-easy 15 API for the first configuration; if it changes, `wg_configure` fails with a message and the settings can still be made in the interface.

## As built (2026-11-25)
Findings of the rehearsal (throw-away stacks on the development machine, a real tunnel from a client container):
- **The default firewall hooks do not work with Docker's nftables.** They call `iptables` (the legacy tables) with `FORWARD` policy `DROP` in nftables: the tunnel came up but the LAN was unreachable. The hooks must name `/usr/sbin/iptables-nft`, as version 14's did.
- **The default NAT device is `eth0`**, wrong on a host whose interface is named otherwise (`eno1`): it is set to the default route's interface.
- **`INIT_IPV4_CIDR` is ignored without `INIT_IPV6_CIDR`** (the group must be complete).
- **The default hooks may run twice** (the interface restarts after the first setup): the legacy rules are deleted in a loop before the new hooks are saved, so nothing is left on the machine after `down`.
- **The API accepts HTTP Basic authentication** (`admin:<password>`), which makes the script possible without a session.
- `make check-migrate` now runs the VPN: client and server key survive an export and import.
- **Not done**: a tunnel from a real device over the Internet (only a client container on the same machine was tried); the automatic removal of the version 14 volume.
