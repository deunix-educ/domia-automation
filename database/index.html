    Database¶

    PostgreSQL 16, accessed through sqlx. Migrations live in crates/dominet-store/migrations/, are embedded in the binary and applied by dominet migrate (never automatically at startup). Running it again has no effect.

    Conventions¶

    • Primary keys are BIGINT GENERATED ALWAYS AS IDENTITY (the WebSocket contract uses integer device_ids).
    • Timestamps are timestamptz in UTC; display uses Europe/Paris (the TZ setting).
    • No PostgreSQL enums: TEXT + CHECK constraint (easier to evolve).
    • updated_at is maintained by a trigger (set_updated_at) on mutable tables.
    • Secrets are never stored in clear: passwords use argon2id, sensitive setting values are encrypted (ADR 0011).

    Tables (R1 to R3)¶

    Table Purpose
    users accounts (role = admin or user, mobile for SMS); case-insensitive unique username
    session server-side sessions (user_id lets us revoke them all)
    login_attempt login attempts for progressive lockout
    app_setting typed settings (str/int/float/bool), is_secret
    navbar_item navigation (admin_only, sort_order, url = path or external URL)
    location locations (rooms, zones)
    message, message_recipient internal messaging (channel, per-recipient delivery status)
    android_device, sms_message, call_log, sms_outbox Android relay (regenerable UUID token, stored as a SHA-256 hash; send queue with acks, ADR 0037)
    schedule_job in-process scheduler: interval, cron or solar
    dashboard an account's dashboards (at most one default, name ≤ 64)
    widget a dashboard's widgets: type, title, references (device_id, scene_id, camera_uuid, no foreign key until R3/R5/R6), presentation, JSON config, HTML content, rectangle grid_col/grid_row/width/height on 12 columns

    | device_group, device_label | device groups (location, icon); state-key labels (name, Lucide icon, unit) | automation.DeviceGroup, DeviceLabel | | device | device: unique Zigbee2MQTT name, type, topic prefix, state (JSONB replaced on every message), last_seen, availability, exposes, tracked / hidden keys (TEXT[]) | automation.Device | | device_state_log | history of tracked keys, one row per device, key and second | automation.DeviceStateLog | | device_image | uploaded device image (resized JPEG, in the database) | image_file | | mqtt_source, weather_station | extra MQTT subscriptions (Linky, SolarMax…); Open-Meteo stations | automation.MqttSource, weather.WeatherStation |

    Automations, scenes and alerts arrive in R4 (the foreign key from widget to device exists since R3, ADR 0025; scenes and cameras will follow).

    Scenes, automations, alerts, energy (R4, migration 0009, ADR 0031)¶

    Table Role
    scene, scene_action scenes (unique name, icon, location) and their ordered commands (position) to devices
    automation trigger / condition / action as JSON (trigger_type + trigger_config…), Rhai script, last_triggered, trigger_count
    automation_run execution journal (instant, cause, status, duration, message)
    alert_rule, alert rules (operator, threshold, severity, cooldown, channels) and alerts (firing / resolved / acknowledged)
    energy_daily_log daily balance Linky HP / HC, solar, heat pump (Wh)

    widget.scene_id becomes a foreign key to scene (ON DELETE SET NULL); schedule_job gains automation_id and accepts the nine solar events.

    Android relay (R5, migration 0010, ADR 0037)¶

    • android_device.token is replaced by token_hash (hex SHA-256, unique): the token is generated by gen_random_uuid() in SQL and shown only once (creation or regeneration). Existing devices keep their token (hash computed by the migration).
    • sms_outbox: an SMS requested from a device (own id = the protocol's message_id, pending / sent / failed, error, ack); origin = a browser SMS or a messaging recipient, never both.

    Devices (R3, migration 0008, ADR 0025)¶

    • device.state is replaced on every message (no merge); the MQTT listener's operations are repository methods, one SQL statement each, idempotent.
    • device_state_log: UNIQUE(device_id, key, ts) per second, batch write with replacement; purge by date (configurable retention).
    • widget.device_id → device(id) ON DELETE SET NULL; a reference to a non-existent device is refused.

    Dashboards and widgets (R2, migration 0007)¶

    • btree_gist extension (created by the migration): enables the widget_no_overlap exclusion constraint, which forbids two widgets of the same dashboard from overlapping (rectangles in cells, bounds included; contiguous widgets are fine). The invariant is therefore guaranteed by the database, even when two moves arrive at the same time.
    • One default dashboard per account at most (partial unique index); cascade delete user → dashboards → widgets.
    • Widget writes of a dashboard are serialised by a row lock on the dashboard (otherwise PostgreSQL reports a deadlock between two concurrent inserts).
    • Details and reasons: ADR 0018 (in French).

    Access from code¶

    • The domain (dominet-domain) defines the validated types (Username, SettingKey, NavbarDraft...) and the ports UserRepo, SettingRepo, NavbarRepo, LocationRepo, DashboardRepo, WidgetRepo; dominet-store implements them with PgStore (store.users(), store.settings(), store.navbar(), store.locations(), store.dashboards(), store.widgets(), store.devices(), store.device_groups(), store.device_labels(), store.state_log(), store.device_images(), store.mqtt_sources(), store.weather(), store.scenes(), store.automations(), store.automation_runs(), store.alert_rules(), store.alerts(), store.energy()).
    • Queries are checked at compile time (sqlx::query!). Offline metadata lives in .sqlx/ (tracked by git): after changing a query or a migration, run make sqlx-prepare; make sqlx-check (part of make ci) verifies they are up to date.
