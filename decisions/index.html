    Architecture decisions: index by theme¶

    The full records are the ADRs in adr/ (context, options, decision, consequences). Each exists in English and in French; this page is the map: what was decided in each area, which decisions were reversed or abandoned and why, and what was deliberately left for later.

    By theme¶

    Architecture and build¶

    One binary with roles; server-rendered Leptos with a WebSocket and Fluent translations; server functions under /sf/; a generic CRUD component for administration pages; an image built with cargo-leptos; a guard that retries a frozen render; browser tests on Marionette/Firefox.

    ADR: 0001, 0007, 0012, 0014, 0017, 0021, 0024.

    Data and storage¶

    ReductStore for raw history, PostgreSQL for current state and aggregates; one replaced state plus a per-second history; images in the database; secrets encrypted at rest with AES-256-GCM; pg_dump and a ReductStore archive for backups.

    ADR: 0002, 0018, 0025, 0028, 0011, 0054.

    Security and access¶

    Server-side sessions with argon2id; a nonce-based CSP; MQTT with one authenticated listener and per-client accounts; hashed, scoped, revocable MCP tokens with an audit trail.

    ADR: 0004, 0016, 0057, 0059.

    Real time and MQTT¶

    rumqttc; typed WebSocket topics that keep the last state; a supervised client that publishes at once or refuses; Zigbee2MQTT ingestion; supervised weather and solar publishers.

    ADR: 0005, 0019, 0020, 0026, 0027, 0030.

    Automation, alerts and energy¶

    Sandboxed Rhai; stored in the same JSON shape the scenarios use; one engine with one queue; a single scheduler with solar events; alert evaluation and lifecycle; the daily energy balance; alerts on real channels.

    ADR: 0006, 0031, 0032, 0033, 0034, 0035, 0036, 0042.

    Messaging and the phone relay¶

    SMTP and SMS channels in a crate of their own; the Android relay keeps its WebSocket contract; hashed device tokens shown once; asynchronous sending with live status.

    ADR: 0037, 0038, 0039, 0040, 0041.

    Surveillance and video¶

    ffmpeg as a supervised subprocess behind a FrameSource trait; a minimal hand-written ONVIF client; YOLOv8n through ONNX Runtime; WHEP live view in WASM through MediaMTX; MediaMTX records and the application indexes; pure-Rust motion detection.

    ADR: 0003, 0008, 0009, 0010, 0043, 0044, 0045, 0046, 0047, 0048, 0049, 0050.

    Observability and operations¶

    A /metrics endpoint; Prometheus and Grafana rules stored in the database; relay of external alerts; Compose base with overlays; MkDocs served by the application; the local pre-push gate; platform alerts read-only in the alerts page.

    ADR: 0013, 0015, 0051, 0052, 0053, 0055, 0056, 0061.

    MCP and the local assistant¶

    An MCP server built into the binary; scoped tokens; a local model that proposes and an application that decides.

    ADR: 0058, 0059, 0060.

    Decisions reversed, replaced or abandoned¶

    Decision What happened Why
    CI on GitHub Actions (initial) Replaced by a self-hosted runner (0013), then by a local gate: the pre-push hook reruns make ci on a clean copy (0015). The public repository keeps the local gate only The workflow only reran make ci, which the developer already ran on the same machine (also the development and production server): 8 to 10 minutes per push, a dedicated system user, rootless Docker, resource ceilings to maintain, and failures hard to read or reproduce. One developer gains nothing from a per-commit trace
    Two Mosquitto listeners, one anonymous on the LAN (0055) One listener with passwords and per-client accounts (0057) The new stack is installed fresh, with no existing MQTT client to spare; an anonymous listener, even disabled by default, reopens the broker to the LAN by one configuration slip
    Two assistant models, 8B daily and 14B for configuration (0060) A single Qwen3-8B Measured 98 % against 96 %, three times faster
    An assistant that renames and modifies existing elements Dropped; the assistant reads, controls and creates Unreliable with the 8B, and a device's name is also its MQTT topic; administration pages do it better
    The local assistant phase (R12) Set aside on 2026-11-18 after trials Reading, control and creation were reliable; modification was not
    Migrating chrono to jiff or time Rejected on 2026-11-20 sqlx 0.9 has no jiff support, and rmcp and schemars keep chrono in the tree anyway. Reopen only on a security advisory, sqlx jiff support, or a need chrono cannot meet
    Leptos 0.9 (0007) Stayed on 0.8.x leptos-fluent required below 0.9 at the time; reconsider when 0.9 is stable and supported
    A pure-Rust or linked H.264 decoder Rejected: ffmpeg subprocess (0003) No mature pure-Rust decoder exists (retina does not decode); ffmpeg-next needs development headers; openh264 cost about twice the CPU and failed on two camera families. Measured: 4 cameras at 22 % of the machine in software, 8 % with VAAPI
    Using an OpenCV binding for motion Rejected: pure-Rust motion (0050) No OpenCV dependency; the algorithm and OpenCV's own details are reproduced and parity is measured against it on synthetic image pairs
    An ONVIF crate Rejected: a minimal hand-written SOAP client (0008) No mature ONVIF crate fits; only a handful of calls are needed, and camera families use different namespace prefixes, so answers are read without relying on them
    Replacing MediaMTX with an all-Rust video stack Deferred (optional phase R9) Only worth it if measurements show a real gain
    Alert acknowledgement of platform alerts Not offered: read-only (0061) Choice of the owner (read-only, one single total in the badge); acknowledgement stays in the tools that own those alerts

    Decided and not yet done¶

    • An arm64 image was never built (0017); required for the Raspberry Pi 5.
    • Short-message sending is deliberately excluded from the MCP tools.
    • Voice assistant, all-Rust video (R9) and hardware extensions (R10) are later phases.

    Conventions that cost something to learn¶

    • Any non-obvious decision gets an ADR with the options rejected.
    • Never publish with -C target-cpu=native; the baseline is x86-64-v2 (0001).
    • Nothing is included from outside crates/ (the image copies only that and .sqlx/).
    • A script can reach the system only through the administration scope (0059).
