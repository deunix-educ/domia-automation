# DomiNet — Production deployment

Clean install in **three commands** on an x86_64 machine with Docker (Compose v2.24 or newer):

```bash
make prod-init      # creates .env: generated secrets, detected network
$EDITOR .env        # review (e-mail, VPN); nothing else is mandatory
make prod-deploy    # certificates, build, start, administrator, initial data, check
```

> These targets deploy **the machine you run them on**. Do not run them on the development machine without a separate project and
> shifted ports (see "Trying it on a development machine"), nor on the old production before the cut-over (R8).

## 1. Prepare the machine

- Debian 13 / recent Ubuntu, Docker with the Compose plugin, `git`, `make`, `openssl`, `curl`, `jq` (optional).
- `mkcert` recommended (`sudo apt install mkcert`): it creates a local authority you install on your devices. Without it `make certs` produces a **self-signed** certificate (browser warning; WebRTC and WebSocket still work once accepted).
- Host name: `hostnamectl set-hostname dominet` gives `dominet.local` (mDNS: `avahi-daemon`). Otherwise `make prod-init` uses `$(hostname).local`; force one with `LAN_DOMAIN=my-name make prod-init`.
- The detection model is not in the repository: `make fetch-model` (official Ultralytics export in a throw-away container) — `make prod-up` does it for you if the file is missing.
- Zigbee dongle (optional): plugged in before `make prod-init`, it is detected (`/dev/ttyUSB0` or `/dev/ttyACM0`) and Zigbee2MQTT is enabled.

## 2. Configure

`make prod-init` copies `.env.example.prod` to `.env` (mode 600, never committed), generates the database, ReductStore, MQTT and Grafana passwords and the Zigbee token, detects the host name and address, and prints the Grafana password. It **refuses to overwrite** an existing `.env`.

To review in `.env` (see `.env.example.prod`, which comments every variable, and `docs/configuration.md`):

| Variable | Role |
|---|---|
| `EMAIL_HOST`, `EMAIL_HOST_USER`, `EMAIL_HOST_PASSWORD`, `EMAIL_RECIPIENT`, `DEFAULT_FROM_EMAIL` | e-mail alerts (application **and** Grafana). Without `EMAIL_RECIPIENT`, Grafana alerts have no recipient |
| `DYNDNS_HOST`, `WG_ADMIN_HASH` | WireGuard VPN (`vpn` profile), see §5 |
| `MQTT_USER`, `MQTT_PASSWORD` | internal MQTT account (DomiNet, Zigbee2MQTT), generated by `prod-init`. **No anonymous access**: every LAN client has its own account (§ 7) |
| `VIDEO_DEVICE`, `RENDER_GID` | **hardware** video decoding (VAAPI, Intel): written by `prod-init` when `/dev/dri/renderD128` exists; on an existing installation, `make prod-video` then `make prod-up`. Without them decoding is in software (about three times more CPU per camera, see `docs/R6-mesures.en.md`) |
| `DOMINET_MASTER_KEY` | encrypts secrets in the database (camera passwords). Generated on first deployment if empty. **Copy it off the machine**: without it a restore loses these secrets |

`make prod-guard` (run by the deployment) refuses a missing, empty or default `.env`.

## 3. Deploy

```bash
make prod-deploy
```

Runs: `prod-guard`, `certs` (if `certs/cert.pem` is missing), `export-ca`, `prod-up` (builds the image, starts the stack and waits until every service is healthy), `prod-superuser` (asks for the administrator name and password, or reads `DOMINET_ADMIN_USER` / `DOMINET_ADMIN_PASSWORD`), `prod-seed` (initial data, alert rules) and `prod-health` (nginx → application, no service in a restart loop).

Migrations are applied at start-up by the `migrate` service. Then open `https://<LAN_DOMAIN>`.

### Devices: trust the certificate

With mkcert, install the authority on each device by opening `http://<LAN_DOMAIN>/dominet-ca.crt` (deliberately also served over HTTP, a new device not having the CA yet), then accept it (Android: Settings → Security → Install a CA certificate).

## 4. Update

```bash
make prod-update          # backup, git pull --ff-only, rebuild, restart, check
NOBACKUP=1 make prod-update   # no backup      NOPULL=1: no git pull
```

A failed backup cancels the update. Migrations are replayed by `migrate`.

## 5. Remote access — WireGuard VPN (optional)

Set `DYNDNS_HOST` (public name of your router) and `WG_ADMIN_HASH` (wg-easy UI password: `docker run --rm ghcr.io/wg-easy/wg-easy:14 wgpw 'password'`, doubling the `$` in `.env`), forward UDP 51820 on the router, then `make prod-up`. The `vpn` profile is enabled only when `WG_ADMIN_HASH` is set. wg-easy uses the host network (`iptables-nft`); UI on port 51821. If needed add the tunnel addresses to `WEBRTC_ADDITIONAL_HOSTS` and `CERT_EXTRA_SANS` (then `make certs`).

## 6. Backups and restore

An automatic backup runs daily at 03:00 (`BACKUP_HOUR`): PostgreSQL (`pg_dump`) and an archive of the ReductStore volume, SHA-256 sums, 7 days kept (`BACKUP_RETENTION_DAYS`), in the `backups-data` volume. `make prod-backup` runs one now. Full restore procedures: [docs/backups.md](docs/backups.md). Regularly copy the `backups-data` volume **and** `DOMINET_MASTER_KEY` off the machine.

## 7. Services and access

| Access | Address |
|---|---|
| Application | `https://<LAN_DOMAIN>` |
| Documentation | `https://<LAN_DOMAIN>/docs/` (behind the login, FR/EN) |
| Grafana | `https://<LAN_DOMAIN>/grafana/` (anonymous viewer; administrator `admin` / `GRAFANA_PASSWORD`) |
| WebRTC video | `https://<LAN_DOMAIN>/webrtc/` (through nginx); RTSP `rtsp://<host>:8554/<uuid>` (user name and personal password from My account → Camera access, see [Camera access](docs/camera-access.md)) |
| Zigbee2MQTT (`zigbee` profile) | `http://<host>:8080`, token `ZIGBEE_AUTH_TOKEN` |
| Adminer | `ADMINER=1 make prod-up`, then `http://127.0.0.1:8181` (SSH tunnel: `ssh -L 8181:127.0.0.1:8181 user@server`) |
| MQTT | host port 1883, **password required**; one account per client: `make prod-mqtt-user NAME=linky` (prints the password once; topic `linky/#` by default), `prod-mqtt-users`, `prod-mqtt-del` |

Prometheus and ReductStore are not published on the host. DomiNet's `/metrics` stays internal.

## 8. Handy commands

```bash
make prod-ps                     # status      make prod-logs S=dominet   # one service's logs
make prod-logs S=dominet N=100   # the last 100 lines, without following (without N: continuous follow, not to be piped into grep or tail)
make prod-passwd U=name          # password (interactive)
make prod-seed-energy            # tracks the keys of the balance and Energy dashboard (DRY=1: simulate)
make prod-dump-context           # YAML snapshot of the installation
make prod-health                 # end-to-end check
make prod-down                   # stop (volumes kept)
```

## 9. Trying it on a development machine

To check the installation without touching anything else: `tools/check-stack.sh <image>` (Compose project `dominet-chk`, shifted ports, throw-away secrets, volumes destroyed afterwards; stop the dev stack first: `make dev-down`). For a real trial deployment use `ENV_FILE`, `PROJECT` and `CERTS_DIR` and shift the ports in `.env` (`NGINX_HTTP_PORT`, `NGINX_HTTPS_PORT`, `POSTGRES_HOST_PORT`, `MQTT_LAN_PORT`); the WebRTC ICE port 8189 is fixed (one stack at a time).

## 10. Demo

`cp .env.example.demo .env.demo`, edit the passwords, then `make demo-up`: application over HTTP on `:8080`, Grafana `:3001`, a fake camera `rtsp://mediamtx:8554/demo-cam-1` to declare in the interface. `make demo-down` stops it.

## Dev / prod differences

| | dev (`make dev-up`) | prod (`make prod-deploy`) |
|---|---|---|
| Services | PostgreSQL, ReductStore, Mosquitto, MediaMTX | full stack + nginx |
| DomiNet | run from sources (`make dev-run`) | container, non-root user |
| Ports | loopback, shifted (1xxxx) | nginx 80/443, LAN MQTT, RTSP, ICE |
| Secrets | throw-away, set by the Makefile | generated `.env`, mode 600 |
